# @house-rules/work-items: notes for agents

WorkItems owns plain-text work items, a configurable status workflow, one holder and a parent column. Version 0.1.0 peers on Effect 4.0.3, domain 0.1.0 and application 0.2.0.

## Mounting

1. Provide `WorkItemAccess`, one unit adapter and `WorkItems.layerMemory(options)` or `WorkItems.layerPostgres(options)` in composition/modules.ts. Postgres needs `SqlClient`.
2. Mount `WorkItemsMount`. Descriptors live in `@house-rules/work-items/contract`; `bindWorkItems(service)` captures the facade once.
3. Register `{ "package": "@house-rules/work-items" }` in the host's migrations list. This workspace uses `{ "workspace": "packages/work-items" }`.

## Options and access

Options are required. `idStrategy` is optional: `"random"` keeps the default hexadecimal ids; `"sequence"` allocates increasing integer strings. Both adapter layers and the raw layer accept it. Postgres persists its sequence across restarts; allocation gaps after rollback are allowed. Start with `WorkItems.presets.board` and set the host's container and holder kinds. States have unique names and open, active, done or cancelled categories. `initial`, every transition target, `claim.toState` and both release states must exist. `claim.holderKind` must be in `holderKinds`. Claim uses that kind with the explicit actor's id. Claim's target must be open or active. Limits are positive integers; maxDepth is a nonnegative integer with roots at zero.

`WorkItemAccess.access(actor, containerOrNull)` returns write, read or none. Missing and denied items both fail `WorkItemNotFound`. The host maps port failures to `WorkItemAccessUnavailable`. `visibleContainers(actor)` returns `{ containers, inbox }`; adapters apply this visibility before pagination. Lists exclude unconfigured container kinds before pagination, even if the port still lists them. An explicit retired-kind container filter fails `WorkItemNotFound`. Keep both port answers consistent.

## Fixed rules

Writes require a live unit and never open one. Pass actors explicitly; never capture CurrentActor. Person operations, including get, list and tree, refuse system callers with WorkItemNotFound. `getForSystem(id)` is a separate read-only operation requiring `work_items:system-read`. Its binding accepts only system callers; people fail `WorkItemsCallerDenied` with kind forbidden, even if they hold that permission. The facade reads storage without an actor or either access-port check and fails WorkItemNotFound only when the id is missing. Cascade hooks `removeContainer(ref)` and `releaseHolder(ref)` are facade-only, require a unit and bypass person access for trusted host lifecycle code. Holder deletion never changes status.

Edit changes content only. `move(id, to)` takes `{ parent: id }` or `{ container: refOrNull }` and moves the whole subtree. It checks write access at the old and target places, configured container kinds, cycles and the entire subtree's maxDepth. Check maxTreeSize only when the container changes. Postgres takes ordered per-container advisory locks before item row locks for structural writes. Move reads only source/target containers and rereads moved rows under locks. Create locks its destination container; import locks its batch containers and referenced parents. Ordinary edits, status and holder writes keep their item row locks. Unrelated containers do not serialize. Container changes during discovery fail WorkItemInputInvalid for retry; never acquire extra container locks out of order. Ids and external notes, relations and history stay unchanged. A child inherits its parent's container. Status transitions apply to setStatus, claim and release. Assign never changes status. Claim rejects closed items and items held by someone other than `{claim.holderKind, actor.id}`. The conditional update accepts an unheld item or the caller's own holder reference. Re-claiming an item already held by the caller in claim.toState returns no events. Claiming an unheld item already in claim.toState needs no self-transition. Release may clear any holder for an actor with write access; an unheld item outside release.from returns no events.

`WorkItems.import(items)` is a trusted facade method; its operation takes `{ items: WorkItem[] }`, requires `work_items:import` and accepts only system callers. Persons fail forbidden `WorkItemsCallerDenied`. It validates content, configured states/kinds, parent links, cycles, depth, size, createdAt <= updatedAt and closedAt non-null exactly for done/cancelled states, preserves full item data, and fails conflict `WorkItemIdTaken` for existing or repeated ids. Parents may be stored already or appear anywhere in the batch. Import advances the sequence in both id modes, never backward, so later switching to sequence is safe. Sequence-mode numeric imports must leave room in Postgres bigint for a next id. Random mode also accepts numeric ids outside that range. A short session advisory lock guards nextval/setval inside one SQL function call and releases before returning, never at transaction end. No table lock or module-wide write lock is used. It returns `{ items, events }` with Created facts. Only import and getForSystem declare WorkItemsCallerDenied, not the shared WorkItemFailure union.

Other write results are `{ item, events }`. Move returns a `Moved` fact with old/new `{ parent, container }`. Event facts are plain contract data, with no envelope, emission or event-log dependency. Attributes accept any JSON value and are never queried. Trees fetch at most maxTreeSize + 1 visible items in one container and fail WorkItemTreeTooLarge if the count exceeds maxTreeSize. The board preset sets maxTreeSize to 500; trees within the limit return descendants to maxDepth. Lists use createdAt/id ordering with an exclusive cursor and maxPageSize. The public SQL view is `work_items_view`.
