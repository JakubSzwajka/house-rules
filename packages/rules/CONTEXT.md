# @house-rules/rules

This is the installable home of the house rules and tool presets. Consumers keep project values, stack-only files such as CI/environment/hooks, prose and wiring tests. They do not copy presets. Version stays 0.18.0 until an approved release.

## Presets

The root plugin key is house-rules. It loads @typescript-eslint/parser but no optional Markdown, CSS, shadcn or Dependency Cruiser peer. recommended checks comment-discipline on JS and TS. testing checks testing-exports-only-in-tests. featuresConfig({appsDir, packagesDir}) and configs.features enable feature-file, feature-builders, no-hand-rolled-surface, no-hand-run-effect on tests, testing exports and no-computed-import on production package/app source. Roots are exact paths or nonempty root arrays, matching layout(). No compatibility preset aliases exist.

The markdown subpath loads @eslint/markdown for relative links to tracked or non-ignored untracked regular files inside the repo. It checks before commit; CI and acceptance still catch linked files left out of the commit. design loads @eslint/css for token/colour/scale/layer checks; shadcn loads @shadcn/lint and the local raw-element check. Component folders own styling. Shell-free host files may use raw elements/inline styles, but retain other checks. nextHost ignores generated Next files only.

The CommonJS dependency-cruiser subpath exports layout(). It loads only hosts.cjs, layout-option-parsers.cjs and layout-patterns.cjs, never node_modules. All forbidden rules are error severity. The README table lists every check; each error links to its stable rule anchor. Intentional config changes update both snapshots and behavioral fixtures.

TypeScript presets are strict, effect, web and next. Effect extends strict and owns the diagnostic plugin block; web supplies browser libs/bundler resolution without replacing it. Next adds host compiler settings. Biome supplies formatting/linting and Tailwind directive parsing; consumer includes remain consumer-owned. Pins and runtime versions are not changed by layout work.

## App and module words

An app has features, read-models, ways-in, composition and main/index. Area option keys are features, readModels, waysIn and composition. The Next host uses waysInLayer app and preserves proxy/instrumentation, next-env, .next and global-error behavior. Generated declarations are exempt only from unresolved imports.

feature-file checks one direct named-import defineFeature value export in each features/<name>/index.ts. Type exports are allowed. Each feature folder contains only index.ts and tests/. Imports use effect, kit/package contracts and same-app read-model contracts only, never other feature indexes. features/index.ts holds feature re-exports, a Features object and type exports, with no other values. Permission lists belong in composition/access.ts. feature-builders restricts defineFeature to feature indexes and keeps defineOperation/bindOperation outside features/. Builders require direct named imports from owning kit doors, with import renames allowed. Namespaces, aliases, barrels, callbacks and dynamic builder imports fail. Non-kit workspace packages cannot import defineFeature/defineWay/endpoint or re-export any kit builder. Finished operations and service-capturing binders remain allowed. Test exemptions use owner-src-relative paths; real kit-root exemptions require matching package names. esm-only-effect keeps its production app/Effect-package fence, including the kits.

Domain modules are packages. There are no folder modules. Feature-folder cycles are checked alongside subject/package cycles. A read model lives in read-models/<name>, has the same doors, imports packages/kits and needs no memory adapter.

Browser-safe graph roots are package contracts, read-model contracts, features/*/index.ts, features/index.ts and ways-in/*/endpoints.ts, including unexposed entries and type-only paths. The graph follows imports transitively. It refuses binding, facade, storage, adapter and server dependencies. Installed contracts are trusted explicitly, including domain/application/identity built dist contracts. Framework domain cannot import any house-rules package, including type-only imports and application/contract.

## Bins

house-rules-pins checks exact dependency/packageManager pins, exact workspace pins and full-SHA Git specs. It reads the declared workspace roots without hoisting or a second lockfile.

house-rules-migrations checks ownership of tables and views, cross-module foreign keys and SQL, migration location, raw transactions and production module/app-opened units. Tests, repository-root scripts/, workspace-top-level scripts/ beside package.json and kit runtime may open units. A scripts/ folder inside production src, a module or a feature has no exception; production app handlers, read models and composition may not. The module list accepts exactly one nonempty workspace/package location. Folder locations are rejected; package names default to the slugged basename and table to <name>_migrations. Real folder identities are unique across locations/names. Migrations directories for both location kinds cannot be symlinks or resolve outside their real module root. Module-root symlinks still work; workspace discovery follows declared roots through them. Both checker and runner reject symlinked SQL files, including in-owner targets, using shared parity fixtures. Existing name/table/adoption rules and workspace/package resolution remain. Runner/checker fixtures share a file path. A second shared fixture pins the mirrored private breakpoint split before SQL lexing. The marker is reserved even inside quotes/comments; the pinned driver requires one command per chunk. The runner sets standard_conforming_strings on first inside its transaction and before each migration chunk. A raw case-insensitive whole-word guard forbids standard_conforming_strings, backslash_quote, set_config and pg_settings anywhere in migration/read-model SQL, including strings, comments and dollar bodies, not unrelated JS prose or the runner's pin. Plain/N strings with backslashes fail in read-model/view-DDL scans; use E or dollar quotes. Read-model SQL uses a token-level bounded SELECT or WITH...SELECT grammar over known published views. Schema-qualified relations, SQL functions, unsafe APIs, unsupported syntax and unknown value/fragment provenance fail. Only proven scalar parameter values interpolate. The legacy ownership scan uses the shared PostgreSQL lexer and blanks ordinary strings. Dollar bodies get a best-effort nested lexical scan, with raw body text as fallback when body lexing fails. PL/pgSQL, DO bodies and dynamic EXECUTE are not semantically analysed; they need review. A SELECT-only role granted published views is a planned follow-up, not phase 1 implementation. Transaction scans remain text heuristics with limits documented in docs/migrations.md. Read models own no migrations.

house-rules-layout cruises production imports and checks package, subject and feature-folder cycles plus package export manifests. Subject edges exclude tests, adapters and root files; package and app-folder edges exclude tests. Ordinary Dependency Cruiser violations remain the dependency check's job.

## Maintenance

Keep source modules small and ship checked-in src without a build. Each source belongs in the typecheck command. Tests exercise exported plugin/presets and real passing/failing graph fixtures; small pure helpers may have unit tests too. Keep all non-retired security, design, comment, pin, test and adapter checks. No new dependency or severity reduction without approval.

Change a rule's source, docs, meta and README table together, then regenerate site/src/content/docs/rules/index.md. Never hand-edit that generated page. Run package typecheck/test and focused static checks. Root check/test and packed-consumer prove final integration, not a replacement for behavioral fixtures.
