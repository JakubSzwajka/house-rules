# Booking app

Read the root AGENTS.md and ../../README.md first. This private reference mounts domain/application, Party, Identity, call-audit, auth-jwt, migrations and Node Host.

## Wiring

- App feature folders under src/features/ each hold only index.ts and tests/. Each index exports one defineFeature with its handler. The handler calls only declared edges. features/index.ts exports only Features. Endpoints, ways, composition, registry, hook and schedule use those identities.
- composition/roles.ts declares member, partner, org-admin and admin built-in roles plus systemPermissions. Party mounts with { builtInRoles } in the STORAGE switch. Composition plugs Party.may() once. PermissionCatalogue is filled from Runtime.permissions after acquisition. The gate checks role permissions; module operations check object relations. MCP is the person and exposes only the two reads. Web alone exposes role management, create_organisation, my_organisations, create_invitation, accept_invitation, list_invitations, revoke_invitation, remove_member, list_people and my_activity. Members have party:create-organisation. Creation bootstraps org-admin through a system assignRole edge with reason "creator of organisation". That role has party:admin, party:read, bookings:read/write/cancel and billing:charge, scoped to the created org. Invitations validate delegation before creation and again at acceptance, consume a hashed seven-day code and assign the optional role through a system edge in one feature unit. Removing staff revokes org-scoped assignments, preserves global roles and refuses the last org admin. Web uses Mean.allow: its same-origin page shows a human confirm dialog before every feature whose lifted needsApproval is true, including cancel_booking, revoke_role and delete_role. The browser dialog is the person's approval, not a separate server attestation. Direct authenticated HTTP clients can also send these calls. Partner keeps Mean.no; MCP keeps Mean.elicitation. Permission and relation gates still apply.
- Identity owns passwords, with IdentityOperations and bindIdentity. modules.ts chooses storage and `Identity.passwords({ issuer, signingKey })`, or ephemeral signing outside production. Identity pairs the issuer with its auth-jwt verifier; OIDC-only options need no passwords provider. Web alone exposes sign_up/sign_in as public system starts, sign_out and person change_password with identity:update. Sign-in refusals are data and commit lock counts. The booking_session cookie is HttpOnly; all session writes require CSRF, including issuance. Main sets the web origin from APP_ORIGIN, or localhost with PORT, and always keeps http://localhost:3000. Plain HTTP, including LAN IPs, uses HttpOnly/SameSite=Lax without Secure; HTTPS adds Secure. The cookie has no __Host- or __Secure- prefix. Web Who uses Identity's configured verifier and accepts bearer before cookie. The demo web issuer is test-only; partner still uses its demo issuer and refuses production.
- First sign-in assigns partner for https://partner.invalid, otherwise member, through a system edge. The verified remote MCP issuer therefore defaults to member. Identity stores no roles. Email never grants admin. The shell-only grant-admin script resolves an existing, bound passwords account through Identity and assigns global admin as system in a script-owned unit. Production needs --yes-production. Ephemeral signing is refused in production.
- Use modulesLayer({ provider?, log? }) from composition/modules.ts. It alone selects adapters from STORAGE, default memory, and requires DATABASE_URL for postgres. Each branch builds the audit Record plug and provides CallWatch with the modules. Postgres shares their PgClient; memory uses log when supplied. plugSockets consumes that watch without selecting storage. Main, ways, features and tests use this one layer. Mount modules, one unit, trace and record; capture services with bindOperation in module/read-model binders; acquire Runtime; then capture it in FirstSignIn. Never authenticate twice or open a production unit in a handler, hook or module.
- Bookings accepts nullable organisationId. Its module asks live Party.isRelated/canAdminOrganisation through declared operation edges, after loading its booking and inside each write unit. Owners or current org staff may show; only owners or current staff with admin permission in scope may cancel. Other show/cancel calls are not_found. MyStuff filters owner-or-staff in SQL over booking_read/payment_read/party_staff_read, never private Party tables. Page For/org filter/Bookings tab narrow this server-filtered list. The seed adds two stable Dave/Acme bookings and one Alice personal booking, with idempotent payments.
- Bookings and Billing own migrations and publish booking_read/payment_read. Identity owns its binding and password migrations. They live in @example/bookings and @example/billing workspace packages. Register those packages in root migrations.json. Shared Party/Identity/call-audit migrations remain registered separately. BookingsOperations, BillingOperations and MyStuffOperations are exported through their contract doors. MyStuff has PG only and an unavailable port without a database.
- scripts/migrate.ts reads MIGRATION_DATABASE_URL and runs root migrations.json before startup. Run pnpm --filter @example/api migrate. ACCOUNTS_SIGNING_KEY supplies a Redacted private P-256 JWK; ACCOUNTS_ISSUER defaults to APP_ORIGIN or localhost:PORT. Empty keys log a development warning.
- scripts/seed.ts is development tooling. The seed package script bundles it, refuses NODE_ENV=production and creates alice/member, bob/partner, carol/Acme org-admin, dave/Acme staff + member and admin/global admin through Identity and Party services. Each email is <name>@example.test with password house-rules-demo. Re-running is idempotent. It adds no public path.
- STORAGE, DATABASE_URL, MCP_AUTH_ISSUER, NODE_ENV, APP_ORIGIN and PORT are the existing environment options. Local issuers refuse production. Remote MCP verifies this resource's audience on every request, including existing sessions.

## Page

`pnpm --filter @example/api build` builds Vite/React/Tailwind and new-york neutral shadcn components from src/ways-in/web/page into dist/web, then bundles the API. Main mounts Node Host staticFiles before the API and excludes /api, /partner, /mcp and /.well-known. Browser calls use only application/contract's Promise client and web/endpoints.ts. The sidebar covers Identity, Bookings/Billing, organisations/invitations, Party roles and people, audit, framework descriptors and a per-tab call log. Passwords and tokens are not logged. Quick sign-in buttons prefill and submit normal sign_in only in a Vite development build, using import.meta.env.DEV. Build with NODE_ENV=development to include them; runtime NODE_ENV alone never enables them. Production page builds omit them. The fixed collapsible audit dock merges tab calls and my_activity by request id and can include reads. Local call history belongs to one person: clear on sign_in, sign_up, sign_out and changed my_profile id, dropping signed-out attempts after authentication. Remount the dock when the profile id changes; no local/session storage persists it. my_activity is person-only and filters actor rows in call-audit SQL; recent_audit remains audit:read-gated and admin-wide. list_people filters in SQL: global admins see everyone, org admins only staff in their administered orgs, others 403. Assign/revoke-role and remove-member forms use that list.

## Proofs

Run the app typecheck and validated test script from the root. PG tests use MigrationsTesting.database per test. composition/tests/database.ts installs a ConfigProvider with STORAGE=postgres and the throwaway database URL; provide databaseTesting to modulesLayer(), never select adapters in test callers. scripts/host-smoke.mjs builds and starts the real Node Host, verifies fail-closed MCP and production refusal, and waits for its own children to exit. It writes ignored dist/main.js, never a source file.

scripts/registry.mjs renders REGISTRY.md without starting the app or reading auth settings. The freshness test never rewrites it. Keep ../../TESTS.md aligned with actual test names and paths. No fake-provider test promises external rollback. P2 stays open. createApp defaults gatePolicy to feature-and-recheck; feature-only skips inner permission rechecks, never feature closures.
