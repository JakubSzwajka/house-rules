# Booking app

Read the root AGENTS.md and ../../README.md first. This private reference mounts domain/application, Party, Identity, call-audit, auth-jwt, migrations and Node Host.

## Wiring

composition/ holds modules.ts, sign-in.ts, access.ts, app.ts and tests/, with no index barrel. Each answers one question: mounts/infrastructure, sign-in, access, startup. This is a review convention, not a lint filename rule. app.ts reads PORT, APP_ORIGIN and NODE_ENV once. sign-in.ts reads sign-in variables once; app.ts passes resolved host settings into its provider factory, then supplies the result to modules.ts.

- App feature folders under src/features/ each hold only index.ts and tests/. Each index exports one defineFeature with its handler. The handler calls only declared edges. features/index.ts exports only Features. Endpoints, ways, composition, registry, hook and schedule use those identities.
- composition/access.ts declares member, partner, org-admin and admin built-in roles plus systemPermissions. Party mounts with { builtInRoles } in the STORAGE switch. Composition plugs Party.may() once. Application supplies PermissionCatalogue from mount descriptors before modules build; Runtime.permissions exposes the same array. The gate checks role permissions; module operations check object relations. MCP is the person and exposes only the two reads. Web alone exposes role management, create_organisation, my_organisations, create_invitation, accept_invitation, list_invitations, revoke_invitation, remove_member, list_people and my_activity. Members have party:create-organisation. Creation bootstraps org-admin through a system assignRole edge with reason "creator of organisation". That role has party:admin, party:read, bookings:read/write/cancel and billing:charge, scoped to the created org. Invitations validate delegation before creation and again at acceptance, consume a hashed seven-day code and assign the optional role through a system edge in one feature unit. Removing staff revokes org-scoped assignments, preserves global roles and refuses the last org admin. Web uses Mean.allow: its same-origin page shows a human confirm dialog before every feature whose lifted needsApproval is true, including cancel_booking, revoke_role and delete_role. The browser dialog is the person's approval, not a separate server attestation. Direct authenticated HTTP clients can also send these calls. MCP keeps Mean.elicitation. Permission and relation gates still apply.
- Identity owns passwords, with IdentityOperations and bindIdentity. modules.ts chooses storage; sign-in.ts declares `Identity.passwords({ issuer, signingKey })`, or ephemeral signing in development/test, the devLocal web issuer only in development/test and the optional MCP OIDC provider. Identity pairs the issuer with its auth-jwt verifier; OIDC-only options need no passwords provider. Web alone exposes sign_up/sign_in as public system starts, sign_out and person change_password with identity:update. Sign-in refusals are data and commit lock counts. The booking_session cookie is HttpOnly; all session writes require CSRF, including issuance. Main sets the web origin from APP_ORIGIN, or localhost with PORT, and always keeps http://localhost:3000. Plain HTTP, including LAN IPs, uses HttpOnly/SameSite=Lax without Secure; HTTPS adds Secure. The cookie has no __Host- or __Secure- prefix. Web Who uses Identity's configured verifier and accepts bearer before cookie. Identity.devLocal supplies the test-only web issuer. It requires NODE_ENV, trimmed and lowercased, to be exactly development or test in the active ConfigProvider and, when present, the host environment. All other values, including missing configuration, fail with unavailable IdentityProviderInvalid, replacing DemoForbidden without changing its kind. sign-in.ts exposes testIssuers signing handles; ways never export them.
- First sign-in assigns member for every verified issuer through a system edge, including remote MCP. Identity stores no roles. Email never grants admin. The shell-only grant-admin script resolves an existing, bound passwords account through Identity and assigns global admin as system in a script-owned unit. Production needs --yes-production. Ephemeral signing is refused in production.
- composition/modules.ts owns the single mount list plus infrastructure and takes resolved identity options from app.ts. app.ts exports modulePlan({ provider?, log?, identity?, settings?, nodeEnv?, issuer? }) for scripts and tests, plus appConfig and createApp. modules.ts alone selects adapters from STORAGE, default memory, and requires DATABASE_URL for postgres. Postgres shares PgClient with the audit Record plug; memory uses log when supplied. createApp accepts an optional modules plan, never a merged service layer. Runtime-backed tests use createApp or kit composition. Raw-service tests and scripts use application's planLayer(modulePlan()). The kit supplies the catalogue before modules build and captures bindings once. Composition resolves Party.may() after modules, then installs FirstSignIn from ways-in/hooks/first-sign-in.ts and forks ways-in/schedules/nightly-cleanup.ts. Main passes both ways explicitly. Each uses Mean.allow. The hook gets fresh request ids and no person authority. The nightly UTC cron 0 3 * * * waits for its first tick, selects due payments and expires each sequentially in its own unit; disposal stops it. No catch-up or multi-process lease. Billing.expireOne is idempotent. Never authenticate twice or open a production unit in a handler, hook or module.
- Bookings accepts nullable organisationId. Its module asks live Party.isRelated/canAdminOrganisation through declared operation edges, after loading its booking and inside each write unit. Owners or current org staff may show; only owners or current staff with admin permission in scope may cancel. Other show/cancel calls are not_found. MyStuff filters owner-or-staff in SQL over booking_read/payment_read/party_staff_read, never private Party tables. Page For/org filter/Bookings tab narrow this server-filtered list. The seed adds two stable Dave/Acme bookings and one Alice personal booking, with idempotent payments.
- Bookings and Billing own migrations and publish booking_read/payment_read. Identity owns its binding and password migrations. They live in @example/bookings and @example/billing workspace packages. Register those packages in root migrations.json. Shared Party/Identity/call-audit migrations remain registered separately. BookingsOperations, BillingOperations and MyStuffOperations are exported through their contract doors. MyStuff has PG only and an unavailable port without a database.
- scripts/migrate.ts reads MIGRATION_DATABASE_URL and runs root migrations.json before startup. Run pnpm --filter @example/api migrate. ACCOUNTS_SIGNING_KEY supplies a Redacted private P-256 JWK; ACCOUNTS_ISSUER defaults to APP_ORIGIN or localhost:PORT. Empty keys log a development/test warning. Production requires ACCOUNTS_SIGNING_KEY, refuses missing keys with typed IdentityProviderInvalid and never adds devLocal. Use APP_ORIGIN over HTTPS for Secure cookies.
- scripts/seed.ts is development tooling. The seed package script bundles it, refuses NODE_ENV=production and creates alice/member, bob/partner, carol/Acme org-admin, dave/Acme staff + member and admin/global admin through Identity and Party services. Each email is <name>@example.test with password house-rules-demo. Re-running is idempotent. It adds no public path.
- STORAGE, DATABASE_URL, MCP_AUTH_ISSUER, NODE_ENV, APP_ORIGIN and PORT are the existing environment options. devLocal and ephemeral passwords signing refuse outside development/test; stable-key passwords signing supports production. Remote MCP verifies this resource's audience on every request, including existing sessions.

## Page

`pnpm --filter @example/api build` builds Vite/React/Tailwind and new-york neutral shadcn components from src/ways-in/web/page into dist/web, then bundles the API. Main mounts Node Host staticFiles before the API and excludes /api, /mcp and /.well-known. Browser calls use only application/contract's Promise client and web/endpoints.ts. The sidebar covers Identity, Bookings/Billing, organisations/invitations, Party roles and people, audit, framework descriptors and a per-tab call log. Passwords and tokens are not logged. Quick sign-in buttons prefill and submit normal sign_in only in a Vite development build, using import.meta.env.DEV. Build with NODE_ENV=development to include them; runtime NODE_ENV alone never enables them. Production page builds omit them. The fixed collapsible audit dock merges tab calls and my_activity by request id and can include reads. Local call history belongs to one person: clear on sign_in, sign_up, sign_out and changed my_profile id, dropping signed-out attempts after authentication. Remount the dock when the profile id changes; no local/session storage persists it. my_activity is person-only and filters actor rows in call-audit SQL; recent_audit remains audit:read-gated and admin-wide. list_people filters in SQL: global admins see everyone, org admins only staff in their administered orgs, others 403. Assign/revoke-role and remove-member forms use that list.

## Proofs

Run the app typecheck and validated test script from the root. PG tests use MigrationsTesting.database per test. composition/tests/database.ts installs a ConfigProvider with STORAGE=postgres and the throwaway database URL; provide databaseTesting to planLayer(modulePlan()) for raw services, or provideMerge it into the plan's infrastructure before createApp. Never select adapters in test callers. scripts/host-smoke.mjs builds and starts the real Node Host, verifies fail-closed MCP, typed production missing-key refusal and production GET / plus sign_up with a temporary P-256 key on a free port, and waits for its own children to exit. It writes ignored dist/main.js, never a source file.

`pnpm --filter @example/api map` prints the app map; `--json` and `--mermaid` select formats, and `--write` refreshes MAP.md. scripts/map.ts acquires memory modules without sign-in providers and with a frozen clock. Literal registry imports, descriptors and manifests supply source paths through the rules app-map helper. Unknown or ambiguous ownership fails. The MAP.md freshness test compares without writing.

scripts/registry.mjs renders REGISTRY.md by acquiring the composition, including modules, runtime and auth plugs from config. It never starts the HTTP Host or serves traffic. The freshness test never rewrites it. Keep ../../TESTS.md aligned with actual test names and paths. No fake-provider test promises external rollback. The gate at feature start checks every closure permission. Every inner call rechecks its own permission against the permissions loaded at start.
